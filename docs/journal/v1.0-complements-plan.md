# v1.0 — compléments : plan

Dernière mise à jour : 30 oct. 2026

Le porteur réintègre dans la v1.0 quatre éléments mis de côté : raccourcis morts du menu Démarrer (D20), suppression des tâches planifiées et services orphelins (D47), applications du Microsoft Store (EF-04), progression détaillée de la désinstallation. Règles absolues : aucune opération destructive sur la machine de développement, tout passe par la quarantaine, `dry_run` vrai par défaut.

## Principe des exceptions à la liste noire

La liste noire existante (`PROTECTED_NAMES`, `PROTECTED_KEY_NAMES`, arbres protégés, racines exactes) **n'est ni modifiée ni contournée** par les règles générales : `check_path` et `validate_key` refusent toujours ces emplacements. Chaque exception est une **fonction de validation dédiée** de `safety.rs`, propre à un type d'élément et à une forme exacte, appelée juste avant d'agir (règle 3). Chacune a un test par cas autorisé et un test par cas voisin refusé.

| Exception | Autorisé exactement | Toujours refusé (testé) |
| --- | --- | --- |
| Raccourci du menu Démarrer | fichier `*.lnk` strictement sous `%APPDATA%\…\Start Menu\Programs` ou `%PROGRAMDATA%\…\Start Menu\Programs`, sans point d'analyse sur le chemin | les racines ; un dossier ; un autre fichier (`.url`, `.exe`, `desktop.ini`) ; un `.lnk` sous `Start Menu` hors `Programs` ; un nom protégé ou un dossier d'outils Windows sous la racine (`Administrative Tools`, `Windows Tools`, `Accessibility`, `Accessories`, `System Tools`, `Windows PowerShell`, `Maintenance`…) ; un chemin avec `..` ; une exclusion de l'utilisateur |
| Sous-dossier du menu Démarrer | dossier strictement sous une des deux racines, **vide** au moment d'agir | la racine ; un dossier non vide ; les mêmes noms refusés que ci-dessus |
| Tâche planifiée | tâche hors de `\Microsoft\`, dont toutes les actions sont `Exec` et dont chaque exécutable est un chemin local absolu, absent, hors `%WINDIR%` | tâche sous `\Microsoft\` (toute casse) ; action COM, courriel ou message ; commande relative ou à variable non résolue ; exécutable présent ; exécutable sous `%WINDIR%` |
| Service | service Win32 (propre ou partagé), arrêté, exécutable local absent hors `%WINDIR%`, sans service dépendant, compte intégré ; **et** sa clé `HKLM\SYSTEM\CurrentControlSet\Services\<nom>` exactement | pilotes noyau et système de fichiers ; service en cours ; hébergé par `svchost.exe` ; image, `ServiceDll` ou texte d'image sous `%WINDIR%` ; service dont un autre dépend ; compte utilisateur (mot de passe non restaurable) ; la clé `Services` elle-même, une sous-clé de `<nom>`, une autre clé de `HKLM\SYSTEM` |
| Dossier de paquet du Store | `%LOCALAPPDATA%\Packages\<PackageFamilyName>` exactement, nom de famille bien formé, paquet absent de la liste des paquets installés lue juste avant d'agir | `Packages` lui-même ; un sous-dossier d'un paquet ; un paquet installé ; une liste des paquets vide ou illisible ; une famille `Microsoft.*`, `MicrosoftWindows.*`, `Windows.*` ou d'éditeur `cw5n1h2txyewy` (Windows) |
| Clés du paquet | `HKCU\Software\Classes\Local Settings\Software\Microsoft\Windows\CurrentVersion\AppContainer\Storage\<pfn>` et `…\AppModel\SystemAppData\<pfn>` exactement, mêmes conditions | les clés parentes ; une sous-clé ; un autre nom ; un paquet installé |

## Étapes (un commit par étape)

### 1. Raccourcis morts du menu Démarrer (D20 révisée, EF-07)

| Fichier | Travail |
| --- | --- |
| `shortcut.rs` (nouveau) | Lecture d'un `.lnk` (MS-SHLLINK) : cible locale, type de lecteur (`VolumeID`), lien réseau, bloc de variables d'environnement, descripteur MSI (`HasDarwinID`), AppUserModelID (bloc `PropertyStore`). Verdict : mort seulement si la cible est un chemin local absent, sur un lecteur fixe présent |
| `safety.rs` | `KnownFolders::start_menu` ; `validate_start_menu_shortcut`, `validate_start_menu_folder` |
| `scan.rs` | Racines du menu Démarrer ; sous-dossiers vides ou ne contenant que des raccourcis morts proposés à part, confiance Moyenne |
| `quarantine.rs` | Validation selon la forme de l'élément (règle générale, sinon exception) ; dossiers traités après les fichiers ; restauration à l'identique |

Tests : un par cas « non mort » (MSI annoncé, AppUserModelID, réseau UNC, lecteur réseau, amovible, lettre absente, variable non résolue) et par cas mort ; aller-retour quarantaine dans un dossier temporaire.

### 2. Tâches planifiées et services orphelins (D47 révisée)

| Fichier | Travail |
| --- | --- |
| `tasks.rs` (nouveau) | Trait `TaskStore` (lire le XML, supprimer, réenregistrer, existe) ; implémentation COM `ITaskService` ; analyse du XML (actions `Exec` et autres) ; faux magasin pour les tests |
| `services.rs` (nouveau) | Trait `ServiceControl` ; `ServiceConfig` sérialisable (type, démarrage, démarrage différé, contrôle d'erreur, chemin, groupe, dépendances, compte, nom affiché, description, actions de récupération) ; implémentation SCM (`QueryServiceConfigW`, `QueryServiceConfig2W`, `EnumDependentServicesW`, `DeleteService`, `CreateServiceW`, `ChangeServiceConfig2W`) ; faux gestionnaire |
| `safety.rs` | `validate_task`, `validate_service`, `check_service_key` |
| `quarantine.rs` | Tâche : XML complet écrit dans la session, manifeste, puis suppression ; restauration par réenregistrement (même chemin, même nom). Service : configuration JSON + clé exportée en `.reg`/`.json`, manifeste, puis `DeleteService` ; restauration par `CreateService`, réimport de la clé et des paramètres |
| `scan.rs` | Confiance : tâche au mieux Élevée si l'exécutable est absent depuis plus de 30 jours ; service plafonné à Moyenne |

**Ancienneté de l'absence** : Windows ne note pas la date de disparition d'un fichier. Mesure prudente : date de modification du plus proche dossier parent encore présent de l'exécutable (elle change quand le fichier ou son dossier est supprimé). Plus de 30 jours → Élevée possible ; sinon Moyenne. Une erreur de mesure ne peut que baisser la confiance.

Tests : sérialisation et reconstruction de la configuration avec le faux gestionnaire ; aller-retour avec les faux magasins ; **aucun vrai service ni vraie tâche créé ou supprimé sur cette machine** (vrais essais dans Windows Sandbox).

### 3. Applications du Microsoft Store (EF-04, S)

| Fichier | Travail |
| --- | --- |
| `store.rs` (nouveau) | Trait `PackageStore` ; implémentation `PackageManager::FindPackagesForUser("")` et `RemovePackageAsync` (utilisateur courant seulement) avec progression ; faux magasin |
| `inventory.rs`, `model.rs` | `AppKind::Store`, `InstallerKind::Msix`, nom complet et nom de famille du paquet ; exclusions : framework, ressource, bundle, stub, `SignatureKind::System` |
| `engine.rs` | `list_apps` fusionne Win32 et Store ; `uninstall` d'un paquet ; restes : dossier `Packages\<PFN>` et clés exactes |
| `scan.rs` | Restes orphelins de paquets désinstallés (confiance Moyenne) |

**Écart** : l'API WinRT (crate `windows` 0.62, SDK 10.0.26100) n'expose pas l'attribut « NonRemovable ». Les applications intégrées non supprimables sont signées `System` et sont donc exclues ; si Windows refuse malgré tout la suppression d'un paquet, l'erreur est affichée et rien n'est modifié.

Annulation pendant une désinstallation MSI : le gestionnaire renvoie `IDCANCEL`, Windows Installer annule proprement (retour arrière) ; pour un `.exe`, inchangé (D35 : on arrête d'attendre sans tuer).
